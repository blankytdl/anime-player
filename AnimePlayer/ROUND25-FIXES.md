# Build 25 = round 25 fixes (full build: unzip, run build.bat; Lua and C# were reviewed by hand and a block-balance check only - not compiled or run)
1. Double-click on an empty player: input.conf no longer binds MBTN_LEFT_DBL to plain `cycle pause` (it never sent `ap-dblclick`). Now `script-message ap-dblclick`; empty player re-opens the last OPENED video (also if it was finished) at its saved position.
2. Resume: videos now continue where they were closed (auto_resume=yes in script-opts/ap-resume.conf). Path keys normalised (C:/x vs C:\x were different entries).
3. Queue tab: double-click opens a row (first click selects), moved/dragged/up/down row stays selected (selected_index), menu closes when the video opens.
4. Zoom: one FORCED zoom button/key (Ctrl+Alt+S): fills the window, black bars cropped, stays on for next files; the old "restore view" never saved the view - fixed.
5. Snap: quarters use Windows-like corner zones (before: pointer had to be within 4 px of both edges), edge RESIZES no longer snap/restore, invisible frame borders compensated.
6. input.conf: removed duplicate MBTN_LEFT_DBL lines, `f frame-step` clash; middle click uses midclick-jump script (Settings value works).
7. Queue: after a move the row is re-selected through uosc's `select-menu-item` (uosc ignores selected_index on menu updates). The Playlist tab already selects the dropped row natively (Menu:move_selected_item_to) in the uosc source you sent; the mouse-drag reorder comes from patches 54-59.
8. Zoom: manual_zoom.lua's zoom-mode-fit/fill/crop messages are no longer sent by any button/key; ap-video.lua's forced zoom replaces them.
9. Playlist tab: new patch tools/patches/79-playlist-dblclick.json - with the mouse the first click selects, a second click within 0.6 s opens (Enter still opens at once). All patches were simulated against the stock uosc you sent: every anchor matches exactly once.
10. ap-queue: duration cache keys normalised (C:/x vs C:\x); 00-thumbfast-path sets thumbfast-mpv_path through the native script-opts table (a comma in the folder name broke it).
11. Smoother actions (new scripts/ap-smooth.lua carries the mpv options, because with the anime build AnimePlayer's own mpv.conf is never installed): seeks are exact + async (held arrow keys no longer queue up blocking seeks, and +5/-5 no longer land on a far keyframe); mpv.conf: hr-seek=yes, hr-seek-framedrop=yes, demuxer-readahead-secs=30, cache-secs=60, audio-buffer=0.3; middle-click jump is exact+async; auto-resume now sets `start` in an on_load hook so the video opens AT the saved position instead of showing 0:00 and jumping.
12. RIGHT-CLICK = mpv.net menu (as the README says). My earlier removal of the `MBTN_Right ... show-menu` line was wrong and is reverted: MBTN_RIGHT is bound explicitly to `script-message-to mpvnet show-menu` (the uosc menu stays on the MENU key / hover bar). MainForm.IsMouseInOsc: with osc=no the menu no longer refuses to open in the outer 10 % / lower 22 % of the window (only the bottom 72 px uosc bar keeps its own right-click).
13. Settings window no longer overwrites script-opts/ap-resume.conf with only idle_dblclick (it dropped auto_resume / hint / interval each time Settings was saved).
14. Control bar = the layout of your picture: the ORIGINAL 4-`space` layout is back (2 spaces pushed the groups to the window edges and squeezed the buttons). The three zoom buttons stay (Fit / Fill / Crop) but now run the FORCED zoom: Fit = off, Fill = forced zoom, Crop = forced zoom after cutting the black bars (scripts/ap-video.lua: ap-zoom-off / ap-zoom-fill / ap-zoom-crop; the build's zoom-mode-* messages are no longer used).
15. Double-click only works on the bare video: patches 80/81 (uosc cursor.lua) - over any uosc element (buttons, hover bar, Playlist/Queue/other menus) the double-click is consumed by uosc and never reaches `MBTN_LEFT_DBL`. The 2nd click of a fast double click used to be IGNORED by uosc (that is why a menu row needed 3-4 clicks); it now counts as a normal click, so Queue / Playlist rows open with 2 clicks.
16. Dragging a row: patches 82/83 + ap-queue.lua - a drop (or a move with the arrow buttons) only selects the moved row for 0.6-0.8 s; it can never open/play it.
17. input.conf rebuilt as the ORIGINAL mpv.net input.conf (generated from mpv.net's own default list, 172 `#menu:` entries incl. Jump 5 sec backward, Jump To Next Frame, ...) plus every AnimePlayer binding. Where the anime build already uses a default key for something else, the menu entry stays but shows no key (assign one in the key editor); where the same action lives on another key (e.g. Fullscreen = F, frame step = Ctrl+Right) the entry shows that key. Right-click, double-click and the other AnimePlayer lines are kept. `_ ignore` is the last line so the placeholder key `_` triggers nothing.
18. Key editor (uosc): menu separators are no longer listed as bindings, unbound entries show an empty hint, and MBTN_LEFT_DBL / MBTN_RIGHT can be captured as keys.
19. Window no longer moves while a row is dragged: MainForm.OnMouseMove does not start a window drag while a uosc menu is open (user-data/uosc/menu/type). The old protection only switched `window-dragging` off from the menu script, and the first mouse move could arrive before that.
20. Double-click resume: a finished video (paused at the end, keep-open) now counts as 'nothing playing' too, so a double-click re-opens the last video instead of only toggling pause.
21. 00-thumbfast-path.lua is back to one atomic `change-list append` (comma-safe quoting) - my earlier rewrite of the whole script-opts table could race with ap-responsive (which scales the hover bar with the window).
22. Control bar (your marked buttons): removed the boxed Playlist button, Open File and Equalizer (overlay uosc.conf + fallback patch 77; manifest sha updated). The playlist/queue menu stays reachable with the `w` key and right-click > View > Playlist (now `script-binding uosc/playlist`); Open File = Ctrl+O / right-click > File. The transport group (prev, chapters, frame back, play/pause, frame next, next) is laid out first and is never hidden.
23. Whole bar centred (patches 84-86, Controls.lua): the transport stays in the middle, the groups hug it, and the whole block is then shifted so the free room left and right of the bar is equal.
24. Playlist / Queue panel scales with the player (patches 87, 88): the panel is 92 % of the window width (it follows the window size, also while resizing) and the rows are 8 % SMALLER than stock, so more rows fit. Other menus keep their size; menus with row buttons get room for the title next to the buttons.
25. Window drag fixed: the drag check now reads `user-data/ap/menu-open` ("yes"/"no", set by uosc's Menu in patches 89/90; quotes tolerated). The previous check read `user-data/uosc/menu/type`, which uosc sets to nil on close - it could stay "set" and block dragging the window.
26. Footer of the Playlist menu ("Total ... | Left ... | N files") no longer shows quote marks (patch 92).
27. Middle-click jump is bound inside scripts/midclick-jump.lua instead of input.conf (so the long "Jump forward (length in Settings...)" entry is gone from the key list); the Settings value still works. Ctrl+Alt+S is back to the zoom MENU (Fit / Fill / Crop). input.conf check: every original binding and every mpv.net default menu action is present; the only differences are the ones listed in these notes.
28. Every tab has its OWN "next file" (scripts/ap-queue.lua, `queue_mode=tabs` in script-opts/ap-queue.conf; `queue_mode=after` = the old behaviour): a video started from the Playlist tab goes on with the playlist - the Next key / button and the end of the video alike (the queue used to be pushed in right behind it, so Next read the queue); a video started from the Queue tab goes on with the next QUEUE video and, when the queue is empty, the playlist carries on where it was. A queue video started on an empty player also keeps the queue going. Adding videos to the queue no longer interrupts the playlist.
29. Queue numbering: the playing row says "playing", the waiting videos are numbered 1, 2, 3 ... in play order ("1  up next" while a queue video plays), watched ones keep their check mark. It used to number by list position, so the first waiting video could be "3". (The Playlist tab keeps the list position, so a number is still the episode's place in the playlist - say if you want it relative to the playing video instead.)
30. Several keys for one action: input.conf has a block of extra keys (Ctrl+Space pause, N next file, B previous file, n next frame, Numpad 4/6 jump, M / MUTE mute, Ctrl+Alt+O open, Ctrl+Alt+W playlist, Ctrl+Alt+Q queue) - only keys that were free - and the uosc key editor (F9) has a new row button "Add another key for this action" that adds a second line with the same command instead of moving the key.
31. Build number: BUILD.txt (project root) holds it - now 25. build.bat prints it, stamps it into the exe version (7.1.2.25) and copies BUILD.txt next to mpvnet.exe; About shows "AnimePlayer build 25" on its first line; the player shows it for 2.5 s at start-up (show_build=no in script-opts/ap-smooth.conf turns that off).
